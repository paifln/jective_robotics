# Сервер помощника JECTIVE

Этот сервис позволяет ученикам пользоваться помощником без общего ключа OpenAI в приложении. Готова реализация и шаблоны установки. Развёртывание на публичном сервере, сертификат и реальные запросы OpenAI пока не выполнены.

После обновления от 16 октября ученический токен в Windows-хранилище привязан к адресу сервера. Подмена адреса в `assistant.json` блокирует отправку токена. Старые зашифрованные записи без этой привязки автоматически не переносятся: администратор должен заново настроить доступ через уже описанную ниже процедуру `JECTIVE_ASSISTANT_SERVER` и `JECTIVE_ASSISTANT_TOKEN`. При перевыпуске отзовите прежний токен в реестре и перезапустите службу. Ученику общий ключ OpenAI не нужен; уроки и локальные подсказки работают во время восстановления доступа.

## Если сервера ещё нет

Для Railway подготовлена отдельная [пошаговая инструкция](deploy/railway/README_RU.md). Сам факт наличия конфигурации не означает, что публичный сервер уже запущен.

## Локальная проверка на Windows

На компьютере администратора с Node.js 24 из корня репозитория:

```powershell
./services/assistant/setup-local.ps1 -Model 'ИМЯ_ДОСТУПНОЙ_МОДЕЛИ'
```

Мастер попросит ключ скрытым вводом. Не указывать ключ в строке команды. Создаются новые приватные папки вне репозитория в `%LOCALAPPDATA%\JectiveAssistant` и отдельно `%LOCALAPPDATA%\JectiveAssistantMaster`: ключ OpenAI шифруется AES-256-GCM, мастер-ключ хранится отдельно с ограниченными Windows ACL, ученический токен — через DPAPI текущего пользователя. Это не защита от захвата всей учётной записи администратора. `.env` с ключом не создаётся. Показанная команда запуска сервера использует `runtime.json`; проверка `/healthz` не вызывает OpenAI.

Для подключения уже существующего EXE закрыть его обычным способом, запустить сервер показанной мастером командой и выполнить:

```powershell
./services/assistant/connect-local-app.ps1 -ConfigurationDirectory 'ПАПКА_ИЗ_МАСТЕРА' -ApplicationPath 'ПУТЬ_К_ПРИЛОЖЕНИЮ.exe'
```

Указать приложение, а не Setup-установщик. Помощник получит отдельный локальный токен; общий ключ остаётся только на стороне сервера. Проверка реального чата расходует API-бюджет. Для локального теста установлены квоты 10 запросов в UTC-сутки. Сервер слушает только `127.0.0.1`, поэтому этот вариант не подключает другие ученические компьютеры.

## Подготовка общего сервера

Серверная программа и сервер как компьютер — разные вещи. Код в этом репозитории готов к настройке, но GitHub сам по себе не запускает помощника для учеников. Для общего онлайн-помощника понадобится отдельный постоянно работающий компьютер, доступный через интернет; его можно арендовать как VPS у хостинга. Возможность запуска Node.js на существующем хостинге сайта зависит от его тарифа и настроек.

Порядок подготовки:

1. Получить сервер с административным доступом, возможностью запуска Node.js 24, постоянным диском для квот и входящим HTTPS. Linux-шаблоны ниже используют systemd и nginx. Конкретные ресурсы и бюджет определяются после оценки количества учеников.
2. Получить IP-адрес сервера. Если вы управляете DNS домена `jective.kz`, создать поддомен, например `assistant.jective.kz`, указывающий на этот IP. Это пример адреса, он не создан этим проектом.
3. Выполнить установку службы, защитить файлы и подключить HTTPS по разделам ниже. Использовать отдельный ключ проекта OpenAI и контролировать его расходы.
4. Выдать каждому устройству свой токен, настроить адрес помощника и проверить доступ. Не давать ученикам доступ к серверной панели или общему ключу.

Публикация исходников в GitHub не требует VPS. До развёртывания онлайн-чат не активируется; уроки, редактор и симулятор доступны локально. Локальное тестирование сервиса не требует платного запроса: `npm run assistant:test` использует заглушку OpenAI.

## Где хранится ключ

Ключ OpenAI помещается только на сервере в `provider.secret.json`, зашифрованном AES-256-GCM. Отдельный случайный мастер-ключ нужен для расшифровки. Его нельзя включать в репозиторий, EXE, резервную копию зашифрованного файла или ученические настройки. Сервис расшифровывает ключ в своей памяти; шифрование файла не защищает его от администратора самого сервера.

Ученический токен, создаваемый командой `credential`, начинается с `jt_`. Это другой секрет, не ключ OpenAI. Ученическая сборка отклоняет неподходящий формат и известный префикс провайдера до записи настроек. Совместимые старые токены длиной 43 символа по-прежнему поддерживаются.

Для Linux шаблоны используют:

| Данные | Путь |
| --- | --- |
| Код сервиса | `/opt/jective-assistant/` |
| Зашифрованный ключ | `/etc/jective-assistant/provider.secret.json` |
| Реестр хешей ученических токенов | `/etc/jective-assistant/assistant-credentials.json` |
| Настройки без ключа OpenAI | `/etc/jective-assistant/runtime.env` |
| Отдельный мастер-ключ | `/etc/jective-assistant-master/master.key` |
| Постоянные квоты | `/var/lib/jective-assistant/quota.sqlite` |

Каталог мастер-ключа доступен только администратору. Systemd передаёт файл сервису через `LoadCredential`. Другие закрытые файлы доступны владельцу и учётной записи сервиса, а не остальным пользователям. Для ручного запуска файлы, читаемые Node на Linux, должны иметь права владельца, например `0600`; каталог с квотами также должен быть закрытым. На Windows необходимы ACL — режим `0600` их не заменяет.

На Linux владельцем `provider.secret.json` и `assistant-credentials.json` должна быть служебная учётная запись `jective-assistant`, права файлов — `0600`. Если подготовка выполнялась от root, перед запуском службы нужно передать ей владение этими двумя файлами. Выдача чтения через группу с режимом `0640` не подходит: загрузчик намеренно отклоняет закрытые файлы с правами группы или остальных пользователей. Каталоги конфигурации и квот должны разрешать службе доступ и оставаться закрытыми для остальных. Сам мастер-ключ сохраняет владелец root с режимом `0600` в отдельном закрытом каталоге; его копию для службы предоставляет systemd. Исходный мастер-ключ не нужно передавать во владение службы. Код в `/opt/jective-assistant` служба читает, но изменять его ей не требуется.

## Подготовка

1. Установить Node.js 24 на сервере. Скопировать **только содержимое** `services/assistant` в `/opt/jective-assistant`; приложению сервера не нужны Electron, исходники ученика или дополнительные npm-зависимости.
2. Создать отдельную служебную учётную запись `jective-assistant` без интерактивного входа. Создать закрытые каталоги конфигурации и данных. Не запускать службу от root.
3. Создать криптографически случайный мастер-ключ: 32 байта, записанные 64 шестнадцатеричными символами в закрытый `master.key`. Использовать менеджер секретов или защищённую процедуру администратора; не помещать значение в историю команд.
4. Временно предоставить `OPENAI_API_KEY`, `ASSISTANT_SECRET_FILE` и один источник мастер-ключа (`ASSISTANT_MASTER_KEY_FILE` или `ASSISTANT_MASTER_KEY`) процессу подготовки. Выполнить `node /opt/jective-assistant/provision.mjs seal`. Команда не перезаписывает существующий файл и не печатает ключ. Удалить `OPENAI_API_KEY` из родительской среды после завершения: дочерний процесс не может удалить переменную у родителя.
5. Для каждого ученика задать непрозрачный `ASSISTANT_LEARNER_ID` и выполнить `node /opt/jective-assistant/provision.mjs credential`. Команда один раз печатает новый ученический токен и `registryEntry`. Доставить токен устройству приватно; в реестр записать **только** записи `registryEntry` в JSON-массив. Не сохранять весь вывод в журнал. Срок действия — 30 дней. Отзыв: удалить запись и перезапустить сервис.
6. Скопировать `deploy/runtime.env.example` в закрытый `runtime.env`, выбрать доступную для вашего аккаунта модель в `ASSISTANT_MODEL` и проверить абсолютные пути. Реальный ключ OpenAI в этом файле не нужен. Мастер-ключ не должен находиться рядом с зашифрованной копией в одном архиве.

## Запуск и HTTPS

Для ручного запуска задать серверные переменные и выполнить `node /opt/jective-assistant/server.mjs` (из репозитория также доступно `npm run assistant:start`). Сервис слушает только `127.0.0.1:8787`.

Для Linux установить шаблон `deploy/jective-assistant.service` в каталог системных служб, проверить пути, версию Node и поддержку `LoadCredential`, затем выполнить перезагрузку конфигурации systemd и запустить службу. Шаблон ограничивает права и позволяет запись в каталог состояния. Его применимость к конкретному дистрибутиву требует проверки на сервере.

В `deploy/nginx.conf.example` заменить домен `assistant.example.invalid` и пути сертификатов на реальные. Получить сертификат для собственного домена, проверить конфигурацию nginx перед включением. Публиковать только HTTPS `/chat/completions`. Не открывать порт 8787 во внешний интернет. Прокси ограничивает размер/скорость запросов и число соединений, не повторяет платные запросы автоматически. Не включать журналирование тел запросов или заголовка Authorization.

Локальная проверка готовности: `curl --fail http://127.0.0.1:8787/healthz`. Она не отправляет запрос OpenAI. После развёртывания отдельно проверить действующий/истёкший/отозванный токен, квоты после перезапуска, отмену запроса, HTTPS и отсутствие секретов в журналах. Реальную проверку ответа выполнить с отдельным тестовым токеном и ограниченным бюджетом проекта OpenAI.

## Подключение ученических устройств

При первом запуске приложения администратор задаёт `JECTIVE_ASSISTANT_SERVER=https://ваш-домен` и отдельный `JECTIVE_ASSISTANT_TOKEN`. На Windows приложение хранит этот токен через Electron safeStorage. Общий ключ OpenAI на ученическое устройство не передаётся. В ученическом интерфейсе нет настроек провайдера или ключа.

Человек, управляющий своим компьютером, может извлечь собственный ученический токен. Поэтому доступ ограничен сроком, отзывом и серверными квотами. Не выдавать один общий токен всем ученикам.

## Обновление и восстановление

Перед обновлением остановить службу, сохранить закрытую копию реестра и корректную резервную копию SQLite. Не копировать один файл активной WAL-базы без согласованного backup. Мастер-ключ хранить отдельно. Заменить код, выполнить локальные тесты в рабочем репозитории, запустить службу и проверить готовность. При ошибке вернуть предыдущий код, сохраняя текущую базу квот. Не сбрасывать квоты при обновлении.

Для ротации OpenAI-ключа создать **новый** зашифрованный файл с новым путём, переключить конфигурацию, перезапустить службу и проверить ответ, затем отозвать старый ключ в OpenAI. Не удалять рабочий секрет до успешной проверки замены.

SQLite предназначен для одного сервера и локального диска. Несколько машин требуют общего хранилища квот и распределённого ограничения нагрузки. Журнал содержит только идентификатор запроса, непрозрачный идентификатор ученика и статус; диалоги не сохраняются этим сервисом.
