# Помощник JECTIVE на Railway

Это конфигурация отдельного серверного сервиса. Она не публикует ученическое приложение. 16 октября 2026 сервер фактически развёрнут в Railway: deployment `46c63566-18a0-4858-a133-42b77a8c88ef` имеет статус `SUCCESS`; по HTTPS получены `200` на `/healthz` и `401` без токена на `/chat/completions`. Ответ OpenAI, баланс, облачная квота после перезапуска и работа реальных учеников пока не проверены.

## Первые действия в аккаунте

1. В Railway создать **New Project → Empty Project**, назвать его `JECTIVE Assistant`.
2. После проверки и самостоятельного пуша актуальных файлов подключить GitHub-репозиторий как отдельный сервис. Не подключать старый коммит в ожидании новой конфигурации. Альтернатива — загрузить подготовленный сервер через официальный CLI; авторизацию выполняет владелец аккаунта.
3. Корень сборки оставить корнем репозитория. В настройках сборки сервиса явно указать **Dockerfile Path** `services/assistant/deploy/railway/Dockerfile`; проверку здоровья — `/healthz`, таймаут 60 секунд, перезапуск `ON_FAILURE` с 3 попытками, одну реплику. Dockerfile копирует только серверные `.mjs`, без SDK, `.env`, пользовательских проектов и установщика. Для новых сервисов не использовать **Config File**: 16 октября API Railway отверг эту настройку как устаревшую, а первая загрузка с одним `railway.toml` выбрала Railpack и не собралась. Файл TOML оставлен для старых сервисов; актуальная альтернатива настройкам панели — [Infrastructure as Code](https://docs.railway.com/infrastructure-as-code).
4. Прикрепить **Volume** к сервису с путём `/data`. Оставить одну реплику. Без переменной Railway `RAILWAY_VOLUME_MOUNT_PATH=/data` запуск завершится ошибкой: временный диск не заменяет хранилище квот.
5. Добавить переменные ниже. Не вставлять секреты в GitHub, Dockerfile, команды с аргументами или сообщения чата.
6. После успешного старта получить публичный HTTPS-домен в Networking. Проверить `/healthz`, затем авторизацию, ограничения и квоты после перезапуска. Только после этого настраивать ученические устройства.

## Переменные сервиса

### Windows-мастер для первоначальной настройки

После входа в официальный Railway CLI и создания отдельного пустого сервиса из корня репозитория:

```powershell
./services/assistant/deploy/railway/configure.ps1 -ProjectId 'UUID_ПРОЕКТА' -Service 'UUID_СЕРВИСА' -Model 'ДОСТУПНАЯ_МОДЕЛЬ' -RailwayPath 'ПУТЬ_К_railway.exe'
```

Мастер покажет выбранный project/service/production, попросит API-ключ скрытым вводом, создаст защищённые локальные файлы и передаст значения в Railway через stdin. Значения не входят в аргументы процессов; stdout/stderr CLI не пересылаются в консоль. Каждая операция использует `--skip-deploys`: автоматического развёртывания и запроса OpenAI нет. Предел пилотной проверки — 10 обращений в UTC-сутки суммарно и один одновременный запрос; это не точный денежный лимит.

Это первоначальная настройка отдельного пилотного сервиса с одним локальным тестовым учеником. Не применять её к действующему реестру учеников: она заменяет переменные реестра. При сетевом сбое часть переменных может быть записана; повторить загрузку **той же** конфигурации, не выпускать новый токен:

```powershell
./services/assistant/deploy/railway/configure.ps1 -ProjectId 'UUID_ПРОЕКТА' -Service 'UUID_СЕРВИСА' -ConfigurationDirectory 'ПАПКА_ПЕРВОЙ_НАСТРОЙКИ' -RailwayPath 'ПУТЬ_К_railway.exe'
```

Для подключения тестового приложения после проверки работающего HTTPS-сервера используется `connect-local-app.ps1` с дополнительным `-ServerUrl 'https://ВАШ_ДОМЕН'`. Мастер не запускает установщик. Сам ключ и мастер-ключ доступны администраторам Railway; в ученический EXE они не попадают.

### Ручная настройка

| Переменная | Значение |
|---|---|
| `ASSISTANT_MODEL` | Доступная модель из вашего проекта OpenAI |
| `ASSISTANT_SEALED_PROVIDER_JSON` | Полное содержимое `provider.secret.json`, созданного процедурой шифрования |
| `ASSISTANT_MASTER_KEY` | Соответствующий мастер-ключ: 64 шестнадцатеричных символа; секрет Railway |
| `ASSISTANT_CREDENTIALS_JSON` | JSON-массив из `credentials.json`: ID, SHA-256 токена, срок действия; без исходных ученических токенов |
| `ASSISTANT_DAILY_LIMIT` | Например `10` запросов одному ученику в UTC-сутки |
| `ASSISTANT_GLOBAL_DAILY_LIMIT` | Для первых проверок `10` запросов всем ученикам суммарно |
| `ASSISTANT_CONCURRENCY` | Для первых проверок `1` |
| `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | `50`, чтобы дать ограниченным по времени запросам завершиться |

`PORT` предоставляет Railway. `OPENAI_API_KEY` в этой конфигурации не нужен: сервер открывает зашифрованный секрет в памяти. Данные квот пишутся в `/data/jective/quota.sqlite`, зашифрованный файл и реестр хешей — во временную приватную папку. Исходные переменные секретов удаляются из окружения процесса после старта. Они по-прежнему доступны администраторам проекта Railway: шифрование не защищает от компрометации всей серверной среды вместе с мастер-ключом.

Для получения зашифрованного файла и реестра можно использовать [локальный мастер](../../DEPLOYMENT_RU.md#локальная-проверка-на-windows) или существующую процедуру `provision.mjs seal`. Тестовый локальный токен действует 30 дней и предназначен только для проверки; реальным ученикам выдаются отдельные отзываемые токены. Изменение реестра требует перезапуска службы.

## Проверка и ограничения

Успешный `/healthz` проверяет старт службы и открытие хранилища, но не доступность модели или баланс OpenAI. Проверить отсутствие токена даёт `401`, исчерпанная квота — `429`. Реальный платный запрос проверять отдельным тестовым учеником и ограниченным бюджетом; не включать запись тела запросов или Authorization в журнал.

Повторяемая внешняя проверка без токенов и оплачиваемых вызовов: `npm run assistant:remote:check -- https://ВАШ_ДОМЕН`. Она проверяет семь HTTP-сценариев, запрет cross-origin обращений и заголовки JSON/no-store/nosniff; результат сохраняется в `.verification/assistant-remote-verification.json`. Проверка использует обычную проверку TLS и не следует перенаправлениям. На действующем сервере все семь сценариев прошли 16 октября 2026. Это не проверка доступности модели, денежного лимита или защиты от всех атак.

Railway монтирует Volume от root. Контейнер начинает с инициализации отдельного каталога `/data/jective`, затем до обработки секретов и запросов сбрасывает дополнительные группы и UID/GID до `1000`. Не расширять права всего диска и не запускать несколько реплик поверх одной SQLite. Локальная Linux-проверка подтвердила UID/GID 1000, пустые дополнительные группы, нулевые effective capabilities, mode 0600 и квоту после перезапуска. Сеть контейнера была отключена, ответ провайдера — явно тестовый. Это не проверка инфраструктуры Railway.

Повторяемая проверка: `npm run assistant:container:test` при наличии Docker Linux. Она собирает отдельный образ из серверных файлов, проверяет штатный CMD и точные хеши, создаёт только собственные случайно названные контейнеры/тома и удаляет их после завершения. Новый Linux CI-job запускает её без секретов. GitHub Actions ещё не выполнялись.

Бесплатный тариф и пробные кредиты ограничены и могут меняться; это не обещание бесплатной постоянной работы. Использование OpenAI оплачивается отдельно. Проверить тариф и настройки расходов в собственном аккаунте до запуска. Квота запросов ограничивает количество обращений, но не является точным денежным лимитом.

Официальные источники: [Railway Config as Code](https://docs.railway.com/config-as-code/reference), [Volumes и права](https://docs.railway.com/volumes), [тарифы](https://docs.railway.com/pricing/plans).
