Installed external tool content binding — 2026-10-11

Environment snapshots now cover the CLI executable, the selected ESP32 core, user libraries and every installed packager's tools tree. This includes external ESP32 compiler, SDK, uploader and filesystem tool bytes previously outside the v1 snapshot. The scope is explicitly versioned as cli-selected-core-installed-tools-user-libraries-v2; v1 manifests cannot be reused as v2 evidence. No editable dependency manifest selects which tool directories are excluded.

Before/after successful compile and immediately before upload, the ToolchainService compares fresh content hashes against its in-memory build binding. Changed external tools cannot reuse a previous firmware build. Snapshots reject links, unsupported files, oversized/deep input and cancellation. They are consistency guards, not signed provenance, OS isolation or proof against every replace-and-restore race. Package indexes outside the selected core, arbitrary external processes and environment variables are not covered by this declared content scope.

Eight bounded file streams run concurrently. Directory traversal and hash entry order remain deterministic; byte counts, file metadata after reading, cancellation and error propagation remain checked. Pending streams settle on both successful and failed traversal. There is no timestamp cache. On the actual host, serial reads took 86.73/70.03 seconds and bounded parallel reads 29.50/45.48 seconds for 59,748 files / 6,852,176,031 bytes. Both methods produced the same SHA-256, 05d780d8394605ad310a76c978d1015bd0b80fcc80305f8c4d3852b23cfb5533. Runs overlapped independent checks, so these are observed timings, not a controlled benchmark. The remaining delay is material and further responsiveness work is pending.
