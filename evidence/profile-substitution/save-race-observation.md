Observed before the save fixes

The source Electron substitution run from exec session 92931 failed in the second Save helper: the file still reported revision 1 when the test expected a value greater than 1. The first file write could be observed before the renderer had received its completed-save reply; the next request could therefore still contain the earlier revision. Inspection confirmed writeProject incremented the submitted revision and checked only the current disk revision against the native expected revision, without requiring the submitted revision to match it. This is a retained observation from the tool transcript, not a reconstructed machine test report.

The fix rejects stale/fabricated submitted revisions, serializes renderer saves, synchronizes the current revision before another save becomes available, and binds results to the originating document. Subsequent review uncovered and fixed native path/recovery races when navigation or autosave occurs before a save finishes. The actual disk/SQLite UI evidence is in evidence/save-navigation/ui.json, results.json and edit-results.json. All 449 current unit tests and the three Studio regression scenarios pass. No physical hardware was involved.
