# Offline body-text library search

New pure index/search service searches IDs/titles and localized theory, safety, examples, instructions and manual body text. NFKC/case normalization, trimmed multiword AND queries and exact-ID/title priority retain stable source order. ContentPanel memoizes the bundled-content index by record set/locale, rather than rebuilding it on each query. Project source, private workspaces and credentials are not indexed.

Full537tests/182files PASS,96.34% package branches/per-file thresholds. Typecheck/lint/build PASS. Initial generic inference failed for the lesson/guide/manual union; corrected with a shared typed LibraryRecord UI interface, without changing runtime semantics. Source Electron10.0s searches administrator password (absent from the manual page title), opens the actual matching assistant page and reads the body; earlier grading/forged-write/progress/restart/keyboard/EN-RU-KK empty-search/800px checks retained. Domain tests cover body matches, all-term matching, exact/fullwidth IDs, whitespace, locale isolation and record preservation.

A separate current-host Node microbenchmark over76bundled records reports per-locale indexing about1-3ms and queryp95 below0.5ms across1000queries, with actual query sets/host metadata in search-profile.json. This is domain-workload evidence, not actual UI latency, required4core8GB acceptance or a guarantee for larger future content; indexing/queries should move to a managed worker if measured workload becomes expensive. Human content/translation acceptance, installed/packaged journey, Windows scaling and physical hardware remain pending.
