# Source UI: portable work and returned feedback

The optional Help > Work review interface now prepares a captured project, shows all included source files and package data, requires explicit inspection, accepts portable work into the local workspace, applies entered rubric scores, and exports/receives a feedback file. No classroom dashboard is shown. Local acceptance and portable export are separate actions; cancellation of an export does not imply a file was sent. Import never opens, compiles, uploads or executes the submitted project.

The actual source Electron test uses separate learner and reviewer user-data directories, real ZIP file reads/writes, actual SQLite persistence and a complete reviewer-process restart. Only native file path selection is substituted. It verifies matching submission/assignment IDs, exact context hash, version 1, manually entered synthetic scores 4/5 and 5/5, returned feedback, duplicate acceptance, tampered-context rejection, conflict rejection without grade replacement, unchanged open-project recovery, durable history and native CSV/HTML report export. The fixture grades are test inputs, not an independent human assessment or hardware verification.

Actual positive exports are retained as submission.jective, feedback.jective, scores.csv and scores.html. CSV has a UTF8 BOM, escaped cells and real stored IDs/scores. HTML escapes record text and declares a restrictive CSP. The printable HTML file was exported and checked; physical printing and printer/page-layout compatibility are NOT RUN. Malicious markup/formula handling is covered by separate unit fixtures. Light/dark feedback screens at 800px were visually inspected; an inherited sticky Help navigation overlap was removed.

459 unit tests pass, branch coverage 96.64%. Typecheck, lint and build pass. Final review UI passes; the broader Studio UI also passes against the same implementation. Initial evidence is retained: a recovery assertion sampled before the initial autosave, and report expectations that omitted CSV cell quotes. Those test expectations were corrected against actual output.

Limits: a context digest is not sender/reviewer authentication. Credential detection is heuristic and requires manual inspection. Different feedback for an already graded submission is rejected; explicit correction/version workflows remain unfinished. The domain test covers five separate learner SQLite databases and two shared assignments; the source GUI proof currently covers one learner and one reviewer plus restart, not the full five-learner/two-assignment GUI acceptance gate.
