# Profile comparison bridge and interface

The profile panel now lets users select a previous version and compare it with the selected stored version against the currently chosen component family and logical wiring. The main process resolves both version/hash pairs before constructing the review. Preload validates the structured response; the UI displays changed fields, GPIO changes, wiring diagnostics and explicit physical NOT RUN status. Changing the selected versions or wiring clears the displayed review.

The real Electron exchange scenario now also verifies the comparison bridge and blocking result for unassigned motor wiring, with physical status shown inside the profile panel. It passed; type checking and lint passed. Imported profiles remain user claims and no project mutation or physical action occurs during comparison.

The migration application flow, custom project selection and compiler integration remain incomplete. A result arriving after a selection change still needs cancellation/staleness hardening before this review can authorize a mutation. Published 0.4.0 artifacts are unchanged. E2E evidence is retained in evidence/wip-profile-review-ui/e2e.json.

Subsequent hardening binds each displayed review to the exact selected versions, component family and wiring values. A result arriving after that context changes is discarded with a localized stale-review message. An existing result is also hidden immediately when the rendered context differs, rather than waiting for effect cleanup. The expanded Electron scenario uses an explicitly delayed test-only IPC response, changes the selection while it is pending and verifies no old result is displayed. It passed, with type checking and lint. The delayed response fixture is installed only inside the test's Electron process. Updated evidence is retained in evidence/wip-profile-review-staleness/e2e.json. The review still cannot apply a project mutation; that integration remains incomplete.
