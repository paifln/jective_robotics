# Serial telemetry plot and CSV

Current source displays actual validated protocol telemetry numbers in the device panel. The pure protocol schema is shared with the serial parser without importing native serial libraries into the renderer. Series are separated by captured connection identity and metric, capped at 32 series and 256 points per series. Invalid frames/timestamps and discarded samples are reported; missing values are never replaced with invented zeros. The paused monitor view also freezes the plot.

The graph uses desktop receipt timestamps and explicitly says device identity and units are unverified. Unit labels are user annotations scoped to the selected series. CSV export preserves origin, clock, connection, port, metric, annotation provenance, receipt timestamp, sequence and value, with spreadsheet-formula escaping. Rendering normalizes the numeric scale to avoid overflow with extreme finite values. The SVG adapts to available width, uses theme text color for contrast and has an accessible name. Visual inspection of the captured 660×220 graph confirmed readable labels and a correctly drawn three-sample line.

TypeScript and ESLint passed; all 48 unit/integration tests passed. Unit tests cover independent connections, retention bounds, rejected malformed/missing measurements, series overflow and CSV escaping. The Electron test injects **explicit test fixtures** into the normal serial-event bridge, renders the plot, supplies a unit annotation, exports an actual CSV file and reads it back. It also verifies that ±1e308 samples do not produce NaN/Infinity SVG coordinates. The fixtures are only in the automated test; no fake transport/data is added to the shipping device path. Reports and screenshot are in `evidence/wip-telemetry-plot`.

No physical port was opened for this check. Hardware telemetry accuracy, disconnected-sensor handling, broader accessibility/performance acceptance and on-device verification remain NOT RUN. The graph is a local plotting capability, not authenticated hardware evidence. Published 0.2.0 artifacts are unchanged and the full specification remains unfinished.
