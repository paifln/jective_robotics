# L15 and profile-aware PWM — unpublished work

L15 now has substantive EN/KK/RU text (821 learner-facing English words), three assessment questions and actual Blockly starter/reference projects. Translations remain drafts requiring technical language review. The starter commands 15, 40, 65, 90, then 115 percent; its fifth command fails with PWM_RANGE, leaves the previous valid simulated duty at 90%, and cannot reach DONE. The reference commands 0/25/50/75/100 at 0/200/400/600/800 ms, explicitly commands zero at 1000 ms and prints DONE once. The final variable value 125 is never sent to an output.

The renderer now generates through a project-aware wrapper. It checks PWM capability on the selected profile's actual logical indicator GPIO, including PWM instructions nested in loops, branches and function definitions. Provisional hardware, unassigned wiring, unsupported pin capability and the independently unassigned second indicator channel remain blocked. Default low-level generation without an explicit driver still reports PWM_DRIVER_REQUIRED. The driver configuration is fixed to 1000 Hz and eight bits, with validated GPIO/configuration consistency.

Generated code uses the pin-based Arduino-ESP32 3.x LEDC API: attach and initial zero precede learner commands. Finite duty percentages from 0 through 100 are rounded to codes 0 through 255. Attach/write failures and invalid percentages latch a first error and prevent further learner commands. Binary indicator ON/OFF uses the same attached PWM output with 100/0 percent. An error is not a guarantee that the last electrical output is off; the lesson states this explicitly. There is no claim of measured waveform, brightness or motor speed.

Implementation was checked against the installed pinned core 3.3.12 header and the [official Espressif LEDC documentation](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html), consulted on 2026-10-10. Real Arduino CLI 1.5.1 compilation of the actual L15 reference succeeds for both ESP32 and ESP32-C3. Host C++ execution with explicit Arduino stubs passes assertions for the actual reference sweep, quantization, finite/range errors, attach/write failures, fault latching and subsequent-command suppression. Stubs test generated control flow; they do not test a physical peripheral.

Typecheck, lint, build and all 161 unit tests pass. Package branch coverage is 1145/1223 (93.62%), with unchanged per-file thresholds. Two targeted source Electron tests pass: the actual L15 starter/reference workflow and the existing two-channel PWM simulation workflow. The complete source Electron regression also passes all 32 scenarios in 3.4 minutes, with no skipped or flaky scenarios and JECTIVE_REAL_COMPILER=1. Its invocation, stdout and report are captured in evidence/runs; this is source-build evidence, not a new installed-release check.
