# Numeric messages and L18 after 0.7.0

The working tree now has a printValue instruction and a Blockly numeric-message block in EN/RU/KK. Its label stays learner data, while its value is an evaluated expression. Blockly save/load and locale changes preserve the label, value and function parameter bindings. Both simulation interpreters and the robot worker emit labeled numeric values at the current execution time. Function parameters survive waits.

Formatting is explicitly six decimal places, rounded half away from zero, with negative rounded zero suppressed. Finite values are bounded to ±1,000,000,000. The generated C++ implements the same integer/fraction formatting rather than depending on Arduino floating-print overflow conventions. It validates the value and expression-error latch before emitting a label. Division by zero and range faults therefore cannot print a misleading measurement=0.000000 or continue to later messages.

scripts/print-value-check.mjs compiles and executes the generated C++ against an explicit host Serial stub, checks positive/negative values, boundaries, rounding, invalid ranges, nonfinite values, latched errors and prefix suppression. It also compiles the sketch with the actual installed ESP32 core. This is host/compiler evidence, not a physical serial-output or upload test. The repeatable command is npm run print-value:check.

L18 is now an authored draft lesson with full EN/KK/RU structures, 1004 learner-facing English words, three explained discussion assessments, automatically checked practice, a starter/reference artifact and the two-input scenario. The unguarded starter fails at the disconnected distance input. The reference records ten committed samples, emits voltage/distance/time labels with actual values, leaves three distance cells blank, and recovers at 1000 ms. The independent 100 ms / twenty-sample challenge produces six invalid distance rows without changing the fault duration. A separate valid-zero trial retains zero as a number.

The lesson is registered in the learning library; its native Electron test loads both artifacts through actual lesson buttons, verifies the supplied world, checks actual numeric messages and downloads the corresponding CSV files. Model sensor expressions still require a hardware driver before C++ generation, so L18 itself is executable in simulation and does not claim a validated physical sensor connection. Technical translations remain draft-review-required. The master curriculum has 18 of 60 authored lessons; the remaining 42 and the other software/hardware acceptance gaps remain.

These changes are not in the immutable published 0.7.0 installer/source archive. Current working-tree proof is under evidence/numeric-messages and evidence/L18; inspect exact reports for scope. The earlier evidence/dashboard record describes the foundation before numeric telemetry and full lesson registration.
