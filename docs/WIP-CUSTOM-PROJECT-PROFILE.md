# Custom profiles selected by projects

Studio now lists stored custom profile versions alongside bundled boards. Choosing a custom version embeds its complete validated definition, version and canonical SHA-256 in the project. Indicator generation and wiring validation use that embedded definition. Saving, exporting, autosaving and compiling verify identity/version/hash; the compiler service also independently rejects altered bindings before CLI invocation. Built-in definitions cannot be overridden by an embedded snapshot, and legacy bundled projects retain their original hash format. Logical wiring is cleared on selecting a profile and previous build state is invalidated.

Projects and portable archives retain the embedded custom definition, allowing resolution without a separately installed registry. Lesson projects inherit the selected binding. Save completion checks all current project fields before clearing the dirty indicator; changes to profile metadata or worksheets during a save therefore remain unsaved. Compilation results also check version/hash and wiring before being attached to the current project.

All 111 unit/integration tests passed with aggregate branch coverage 844/924 (91.34 percent) and unchanged per-file thresholds. Type checking and lint passed. A real source Electron scenario selected a custom GPIO4 profile, generated GPIO4 indicator code, saved and reopened its exact definition, rejected tampered autosave data and successfully compiled it using the real pinned Arduino CLI/ESP32 toolchain. Together with the English studio scenario it passed in 37.5 seconds. The actual compiler manifest and sketch are retained in evidence/wip-custom-project-profile. Three related Electron scenarios for Unicode persistence, profile exchange and registry restart also passed in 11.1 seconds; their structured report is retained separately as related-e2e.json.

This does not establish physical GPIO operation or upload. Custom imports remain user-provided claims; only the existing ESP32/C3 FQBN/core combinations and indicator generator are supported. Reviewed migration application, complete driver adapters and full master acceptance remain incomplete. Older strict-schema releases reject the new profileDefinition field; custom projects are supported by current source, not the unchanged published 0.4.0 installer.
