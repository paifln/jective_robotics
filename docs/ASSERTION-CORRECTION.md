# Correction to earlier C++ host verification evidence

While integrating L39, the native-case table showed a valid initialized/armed case as rejected. That discrepancy led to a direct compiler probe. The pinned Zig 0.15.2 C++ driver defines `NDEBUG` for the earlier `-O2` command. Assertions were therefore removed, including setup calls written inside `assert`. A native process exiting zero under those flags was insufficient evidence that its asserted invariants were checked. This correction supersedes earlier claims about assert-based host checks made without `-UNDEBUG`; it does not invalidate independently observed Arduino compiler/artifact results, JavaScript tests or UI/file checks.

All sixteen affected host verification scripts now use `-UNDEBUG` and forcibly include `tests/firmware/assertions-required.h`. That header refuses to compile when assertions are disabled. `node scripts/assertion-probe.mjs` proves three behaviors: the earlier command omits an assertion side effect; the new guard rejects that disabled configuration; and the corrected command executes the assertion. These are actual local compiler/process results, not source inspection alone. Evidence is in `evidence/assertions/probe.json`.

Runtime and L39 checks were rerun with enabled assertions. The corrected native fixture observes Accepted for admitted initialized/armed cases, InvalidInput for invalid bounds, and RuntimeRejected for missing initialization/arming. The corrected learner helper is checked against all eight real API cases; the starter's false-success result is deliberately reproduced. Hardware boundaries are still substituted and no real RTOS safety task or physical motor is run.

Legacy checks are revalidated serially by `scripts/revalidate-host-assertions.mjs`. Inspect both `evidence/assertions/revalidated/host-only.json` and `with-firmware.json` for the actual completion and exit status of every script; a source flag change alone is not verification. The earlier general test-results snapshot is retained under `evidence/assertions/unscoped-test-results-snapshot` solely as historical data, not proof that every copied report was revalidated. Newly scoped reports and child-process logs identify the checker that produced them. Historical installer files are unchanged.

The original L38 C++ report is retained. Its corrected assertion-enabled result is written to `evidence/assertions/revalidated/types-scope/compiler.json`. Older runtime/L39 reports with disabled assertions are preserved under `evidence/assertions`; use current source-matched receipts for current claims. Physical upload, emergency-stop latency, Windows 10 and clean-machine deployment remain separate unverified acceptance work.
