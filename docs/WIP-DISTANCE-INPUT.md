# Explicit distance validity and injected faults — unpublished work

The simulator scenario accepts an optional strict distanceInput model with an initial value and up to 2000 strictly time-ordered events. Values are metres, finite and nonnegative, or null for missing data. A value above the configured robot distanceMax becomes an outOfRange reading; a missing value becomes missing. Both expose distance=null. A valid zero remains distance=0 with valid status. Input provenance is explicitly injected, separate from the existing ray model. Injected values are scenario inputs, not physical measurements.

Robot state now includes distanceStatus and distanceSource. Its response schema rejects valid/null and invalid/numeric contradictions. The distance-valid sensor expression returns a boolean-like numeric result. Reading distance while invalid throws DISTANCE_READING_INVALID rather than inventing zero or preserving a stale measurement as current. A guarded conditional or short-circuited AND can handle invalid data without reading it. Execution faults stop virtual motors. The injected model is copied by scenario validation, so mutating the original input object cannot change its timeline after construction.

The existing ray path still uses its historical capped numerical distance model. This change does not establish a physical echo, calibration, beam width, minimum measurable distance or driver compatibility. The ray model's saturation semantics and the actual L17 calibration activity require further work. Hardware generation of sensor expressions remains blocked with SENSOR_DRIVER_REQUIRED.

Tests cover missing/range/zero/boundary distinctions, ordered event validation, exact time selection, invalid input rejection, unsafe direct reads, short-circuit guards, input-copy isolation and contradictory state rejection.
