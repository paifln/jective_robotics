# Logical and fractional expression semantics

Two mismatches were found between the shared numeric IR, simulators and generated C++. Both simulators eagerly evaluated the right operand of logical AND/OR, unlike C++ short-circuit evaluation. The generator emitted whole-number literals as integers, so `1 / 2` could evaluate to zero before assignment to a double variable. Current source skips an unnecessary right operand in both simulators and emits integral-valued expression literals with a floating-point suffix, producing `1.0 / 2.0`. Exponent-form and fractional literals already denote floating-point values and remain unchanged. Wait durations, repeat counts and GPIO literals retain their distinct integer roles.

Strict TypeScript and ESLint passed; all 46 unit/integration tests passed. New tests use guarded division by zero to verify skipped logical operands in both simulators and check fractional state. `npm run firmware:expressions` generates real C++ from an IR fixture, compiles and executes it using the verified host C++ compiler with explicit Arduino stubs, and checks 0.5 division and both logical results. It also compiles the generated sketch with the pinned actual ESP32 toolchain. Host compilation/execution and ESP32 compilation passed. Report and generated source are preserved in `evidence/wip-expression-semantics`.

Upload and on-device execution are NOT RUN. These checks address the identified logical/literal defects, not exhaustive numerical parity: directly evaluated division by zero and overflow handling still differ between simulator errors and ordinary C++ floating-point behavior and require further work. The full specification is unfinished; published 0.2.0 artifacts remain unchanged.
