# Timing and two-indicator work after release 0.2.0

Current source contains four authored lessons; L04 has 700 learner-facing English words and complete draft Kazakh/Russian translations. Its starter and reference load as actual Blockly projects. Indicator channel 2 is preserved through Blockly serialization and interpreted independently from channel 1 in both simulators. The original single-channel representation remains compatible. Invalid boolean states and channel numbers are rejected. Physical code generation for channel 2 reports SECOND_INDICATOR_WIRING_REQUIRED instead of assigning a guessed GPIO.

The studio exports an actual JSON trace labelled `origin: simulation`, with captured project identity, revision, duration and the exact executed block program. A previous trace retains its original program metadata if the current project changes. Starting another simulation clears it. Simulation traces do not establish hardware upload, movement or stop reaction time.

The cooperative Arduino template is available for viewing/export inside the offline learning library and as `examples/two-indicator-cooperative.ino`. A test compares the two copies exactly. The template requires three explicitly supplied pin definitions, starts outputs low, checks stop on every loop call, latches stop and uses unsigned elapsed-time subtraction. It deliberately avoids catching up missed phases. The accompanying lesson compares its main-loop execution path with blocking delay and explains drift and limits.

Host C++ execution with explicit Arduino I/O stubs passed startup, boundary times, next-loop stop, stop latch and counter rollover. Actual ESP32 compilation passed with **fixture-only** pin definitions; compilation without definitions failed as intended. No serial port, GPIO or actuator was operated. These checks establish software behavior and compiler acceptance; physical verification and upload remain NOT RUN.

This source is not yet packaged into the published installer or source ZIP. Published 0.2.0 artifacts remain the two-lesson snapshot with their existing hashes. WIP reports are stored separately under `evidence/wip-l04`. The full course remains NOT COMPLETE: 56 lessons are missing and technical translations require review.

Verification of this working-tree app: strict TypeScript, ESLint and all 30 unit/integration tests passed. The seven-scenario Electron run executed the real compiler (no skip): six passed, including both new lesson exports; the original studio scenario failed because it had loaded the previous expected log text before its channel-label assertion was updated. Its isolated rerun passed after updating the assertion to `led channel 1`. Both the failed full-run report and passing rerun are preserved. This is evidence of seven individually passing scenarios, not a claim that the first aggregate run was green. The real compiler scenario accepted valid source and rejected deliberately invalid source. Tests launched the rebuilt source app, not an updated installer.
