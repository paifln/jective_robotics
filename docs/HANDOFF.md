Имя `build_opt.h` запрещено без учёта регистра: ESP32 использует его как параметры компилятора. Обычные `.h`, `.hpp` и `.cpp` доступны. При отказе интерфейс предлагает другое имя; исходные данные не удаляются. Компонент управления файлами разделён на обработчики и разметку.

Перед загрузкой окончательная проверка бинарных файлов и исходников выполняется после длительной проверки SDK. Подтверждено тестом: прежний порядок допускал изменение файла во время ожидания до программного загрузчика, новый порядок отклоняет изменения до его вызова. [Регрессия и 25 успешных проверок](../evidence/evening-20261016/upload-check-order.json). Физическая загрузка не выполнялась.

Снимок результатов компиляции выделен в `packages/toolchain/build-snapshot.ts`: ограниченный манифест, строгое чтение UTF-8, потоковое хеширование бинарных файлов, проверки размера, типа, идентичности и изменений файла. Повреждённая или устаревшая сборка не допускается к загрузке; сообщение подсказывает повторную компиляцию на EN/RU/KK.

Проверка SDK сохраняет полное хеширование содержимого, восемь потоков и прежний порядок хеша. Небольшие файлы используют меньшие буферы; очередь результатов ограничена 1024 записями, метаданные соседних файлов читаются пакетами по восемь. В интерфейсе показаны реальные счётчики проверенных файлов, объёма и времени. Проценты и предполагаемое время завершения не выдумываются; частые обновления счётчиков не объявляются экранным диктором.

Добавлена воспроизводимая проверка настоящего компилятора через интерфейс:

```powershell
# Для проверки из исходников сначала:
npm run build -- --production
npm run compiler:ui:check -- --toolchain "C:\путь\к установленному SDK"

# Для готового приложения:
npm run compiler:ui:check -- --toolchain "C:\путь\к установленному SDK" --application "C:\путь\JECTIVE Robotics Studio.exe"
```

Команда использует отдельный временный профиль и уже установленный SDK. Она создаёт результаты сборки внутри указанного SDK, проверяет корректный и ошибочный код, автосохранение и восстановление. SDK не скачивает, порт не открывает, код на плату не загружает, ИИ не вызывает. Для готового EXE используется временный диагностический порт Chromium только на loopback; main inspector и fuses не меняются. Итоги записываются в `test-results`.
