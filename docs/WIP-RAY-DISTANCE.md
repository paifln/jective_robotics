# Geometric distance model and calibration evidence — unpublished work

The ray model no longer returns a fabricated maximum reading when no surface is within its configured range. It computes exact intersections with world boundaries and rectangular obstacles, selects the nearest forward surface, and reports null/outOfRange when that surface is beyond distanceMax. Noise cannot turn an out-of-range surface into a valid reading; a noisy value outside the permitted range is also rejected. Valid results are rounded to millimetres. The origin is the robot centre, with an ideal zero-width ray. No physical beam, mounting offset or echo behavior is implied.

This replaces the earlier numerical stepping and saturation behavior described in WIP-DISTANCE-INPUT.md. It removes step-size bias at known targets. L07 and L09 now supply explicit target scenarios with a surface two metres from the robot centre. The L07 activity text identifies the supplied target scene. Their tests use actual near/far surfaces instead of relying on an empty scene to invent a far measurement. Programs that read an empty, out-of-range ray without checking distanceValid now fault explicitly.

`node scripts/distance-check.mjs` (also `npm run distance:check`) executes the actual RobotSimulation ten times for each known target at 0.2/0.5/1/1.5/2/2.1 metres. The first five report exactly the expected value in the noiseless model, with zero numerical error and repeatable results. The 2.1-metre target reports null/outOfRange. JSON and CSV tables are retained in evidence/wip-ray-distance. This is geometric simulator verification, not physical sensor calibration.
