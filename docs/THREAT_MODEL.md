# Trust boundaries — development build

The renderer is sandboxed, context-isolated and has Node integration disabled. Preload exposes fixed named methods, not raw IPC, arbitrary paths or shell dispatch. Runtime Zod validation applies to requests/responses; main accepts only the owned window's main frame and local origin. Local asset paths are canonicalized and contained. Navigation, new windows and permissions are denied. CSP permits packaged assets and prohibits renderer network access. No analytics or cloud database exists. Optional assistant network access belongs to main and requires explicit configuration/request.

Untrusted projects/archives do not execute on import. Projects are size-bounded and schema-checked; compiler source is data until an explicit compile. ZIP is decoded in memory with bounded original/packed sizes and exactly two allowed entries. No imported scripts or profile native plugins are executed. Backup databases load read-only with extensions disabled and trusted schema off, reject unknown tables/triggers/views and rebuild schema-validated records into a fresh database. CSV formula prefixes are escaped; content is rendered through React text, not untrusted HTML. The original guide SVG is generated by app code with text values, not imported SVG.

Native dialogs authorize file locations. Project saves use atomic replacement and revision checks; asynchronous save preserves newer renderer edits. Remaining gaps: proven cross-process compare-and-replace, project path junction/symlink policy, file replacement consent consistency, crash/disk-full/read-only/antivirus fault acceptance and full pre-migration backup fixtures. Imported toolchain paths are constrained to data/user, checked by realpath and per-file SHA256, staged, then renamed; a user-selected manifest is not a signed trust root. Administrators must verify the published bundle digest before distribution.

CLI executable/versions and argument construction are fixed, shell disabled. Each compile writes to a unique operation directory. Actual exit status/artifacts drive results; no synthetic progress or success. Upload requires the last successful candidate and matching source/profile/wiring/artifact hashes, an actual enumerated user-selected port and confirmation. Failed compilation removes eligibility. Cancellation uses targeted taskkill for the compiler tree. A compiler still processes malicious source; this build is not an OS sandbox for compiler exploits. Imported toolchain recipes/binaries are executable dependencies needing provenance review. Full child cleanup/fault tests remain outstanding.

Serial framing is bounded and schema-validated; raw and protocol data remain distinct. UTF-8 decoder spans chunks and buffers are bounded. Raw sending rejects reserved protocol lines, including multiline/leading-whitespace variants. Device identifiers are hints, never proof of wiring or compatibility. No host movement controls are available. Experimental device runtime starts disarmed and enforces conservative limits/challenges; arbitrary custom C++, interrupt starvation and hardware faults can bypass software assumptions. Physical safety is NOT RUN.

All desktop builds use an administrator-provisioned managed JECTIVE gateway. The shared OpenAI key and model remain on the server; Windows secure storage protects only the learner token. Renderer credential configuration is denied and preload does not transport supplied configure arguments. Project/export schemas exclude credentials. HTTPS is required except explicit loopback test services. Redirects are rejected, payloads/responses bounded, errors omit provider secrets and requests can be cancelled. User preview governs the question, bounded conversation history and optional selected-file context; provider output is untrusted plain text. Diff apply is explicit and checks all captured source/configuration inputs remain current. No reply auto-executes, compiles, uploads or arms hardware. Test-only dummy tokens/upstreams are clearly isolated.

The server stores the provider key encrypted with AES-256-GCM and keeps its master key separately; a server administrator can still access a key used in server memory. Learner credentials are random expiring tokens with a hash-only registry and revocation on service reload. The gateway has bounded requests/responses, an absolute deadline, concurrency limits and persistent daily SQLite quotas. Logs exclude questions, answers, source and credentials. This is a server implementation and deployment template, not a deployed HTTPS service or verified production OpenAI account.

Application operation metadata and compiler journals are different data. Full compiler journals and exported build reports may contain source excerpts and local paths from tool output. They remain local unless the user deliberately exports/shares them; they must not be described as metadata-only logs.

Outstanding release security gates: comprehensive negative IPC/archive/database tests, denial-of-service and concurrency audits, credential rotation/failure scenarios, reviewed distribution notices, dependency provenance checks and physical/fault testing. Zero npm advisories does not imply complete security acceptance.
