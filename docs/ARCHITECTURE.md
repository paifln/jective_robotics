# Architecture and durable formats

## Enforced browser/native boundary

`npm run architecture:check` follows the actual bundled dependencies of the renderer, all renderer workers, preload and pure contracts. Native Node/Electron/serial imports are rejected transitively; only preload's direct Electron bridge import is permitted. The check also rejects relative server-service imports. It runs before every desktop build. Regression tests deliberately hide native imports behind a shared module. This is a static dependency guard, complementing sandbox, CSP and validated IPC; it does not replace runtime security tests.

## Managed assistant service boundary

Packaged learner builds use the JECTIVE gateway and encrypted learner tokens; provider credentials belong exclusively on the server. Server HTTP lifecycle, input/credential policy, bounded body reads, OpenAI adapter, runtime configuration, private-file reads, encryption and durable quotas now live in separate modules under `services/assistant`. See its README and administrator deployment guide. The server is not bundled into student assets or started by importing its modules. Legacy direct-provider development fixtures remain for compatibility testing, not student deployment.

Electron main owns native dialogs, SQLite, fixed external CLI invocation, actual serial transport, archive import/export and encrypted credentials. Preload exposes named typed methods with Zod request/response validation. Main checks the sender, main frame and local origin. React owns local Blockly/Monaco and presentation; hardware and persistence logic remain in domain services. Main assets use a contained `jective://studio` scheme. No development server is used.

Packages: contracts, profiles/component roles, codegen/shared IR, worker simulator, content, persistence/archives/workspace, toolchain/bundle, devices/framing and assistant. Source and tests are separate. Runtime C++ resides in `firmware/jective-runtime`. Services currently implement the useful paths; more formal interfaces/state-machine events and fault acceptance remain required.

## Project version 1

Stable UUID, name, profile ID, optional resolved profile version/hash, authoritative Blocks/Code mode, exact source, Blockly serialization, revision, optional logical wiring, lesson and world IDs. Main attaches the current profile version/hash on save, autosave, export and compile. A mismatch requires explicit profile reselection rather than silent wiring change. Blocks mode derives source from the workspace. Conversion keeps that workspace but makes source independent. Edited arbitrary C++ is not reverse-translated or simulated.

JSON save uses size-bound reads, temporary sibling fsync and rename with a revision check. SQLite `workspace.sqlite` uses strict tables, WAL, FULL synchronization and transactions for settings, local projects, snapshots, progress, assignments, submissions and grades. Autosave debounces two seconds after editing stops and does not overwrite the external file. Recent local projects reopen as copies; snapshot restoration creates a new project ID. Restoring a backup reads it without extension loading, checks schema/integrity and bounded records, rejects triggers/views and reconstructs a fresh known database. Current records are backed up before replacement. Wider crash, disk-full, lock and concurrent-process acceptance remain.

## Archives

Bounded ZIP `.jective`: exactly `manifest.json` and `content.json`. Manifest format `jective`, version 1, kind project/assignment/submission. Content is schema-validated. No filesystem extraction occurs; unknown entry names, traversal and size excess are rejected. Source is never executed on import. IDs persist across classroom exchange. Identical duplicate submissions are harmless; conflicting ID or learner/version pairs fail. Revised assignments require new IDs. CSV cells are quoted and formula prefixes escaped.

## IR and simulation

The shared instruction model includes indicators, PWM, waits, labelled numeric printing, assignments, conditionals, bounded repeat/while loops, wheel commands, stop and simulator sound events. Expressions include finite numbers, variables, Boolean negation, bounded binary operators and approved simulated sensors. Function validation and lowering live in `packages/codegen/functions.ts`. Nesting, instruction counts and loop budgets are bounded. Supported hardware generation emits deterministic Arduino C++, escaped UTF-8 strings and block-ID comments. The current wait uses Arduino delay; cooperative motor generation remains unfinished. Simulated motion, sensor calls, sound and a second indicator do not acquire hardware compatibility merely by compiling a different program: generation explicitly rejects their missing hardware adapters.

The worker robot model uses 20 ms fixed ticks, differential drive, body collisions, configurable track/radius/speed/acceleration/probe positions and distance range, and seeded optional distance noise. State messages are schema-checked; at most one tick request is pending. Reset terminates the old worker. Per-tick instructions and total duration are bounded. Six local worlds and validated scenario edits share this model. Export includes IR, scenario and bounded state trace. It is not an ESP32/C++ emulator.

## Tools and devices

Toolchain is isolated from global Arduino settings. CLI 1.5.1 and ESP32 core 3.3.12 are enforced. Each compile has unique sketch/output directories and a source/profile/wiring digest, resolved profile, real logs/exit status and artifact hashes. Success requires .bin and .elf. Failed new builds invalidate the prior upload candidate. Upload verifies the latest operation, matching source and every artifact hash; main requires an enumerated explicit port and native confirmation, then closes serial first. Logs are bounded; continuous streaming and extended lifecycle fault tests remain incomplete.

`packages/toolchain/environment.ts` fingerprints actual CLI, selected core, installed tools and user-library content before and after a successful build, and again before upload. It rejects linked paths, oversized/deep trees and observed changes while reading. Metadata alone is not a trusted cache key. Production injects `snapshotEnvironmentInThread` from the desktop infrastructure: a fixed bundled worker, validated input/output, cancellation flag, five-minute watchdog and explicit worker termination keep hashing off the Electron main event loop. Electron workers use `original-fs` for physical SDK files; Node fixtures use ordinary Node filesystem APIs. This is an I/O boundary, not a demonstrated speed improvement. On the current development host, a complete native Electron cycle still took 242–246 seconds, principally two integrity scans of 59,748 files / 6.85 GB. See `evidence/editor-startup/io-comparison.json` for scope and measurements.

Build stages originate at real service boundaries and cross a dedicated schema-validated `build:stage` subscription. The renderer accepts messages for its current project only and localizes them in EN/RU/KK. Stage messages do not represent percentages or successful compilation; the returned build result and artifact checks determine that outcome.

A post-compile SDK mismatch records a failed manifest with both snapshots, the actual compiler exit code and log, and source-file hashes. No artifact hashes or upload candidate are published for that operation. The compile request still rejects `BUILD_ENVIRONMENT_CHANGED`; neither that failed operation nor a previous invalidated build can reach upload. A successful compiler exit with a failed integrity check remains a failed build.

## Renderer and reading tools

Blockly initialization and Monaco initialization have separate lifecycles. Monaco is created on the first Studio visit and retained across navigation, preserving per-file models, undo history and view state. Sidebar focus navigation and active-section semantics live in `StudentUI.tsx`; section transitions respect both the operating-system motion preference and the learner's saved preference. Reading preferences are shared by theory and accessibility controls. Local audio uses the restricted application protocol with bounded single-range media responses. Recorded audio is validated against lesson text and packaged file hashes; missing locale recordings remain explicitly unavailable.

`useProjectBrowser.ts` owns project/snapshot reads independently of list presentation. It rejects stale replies after a project change or unmount, permits one read to succeed when the other fails and preserves a usable prior list on refresh failure. The project view shows dated rows and actionable read errors; persistence remains in the main process.

DeviceService lists actual OS ports, opens only an explicit current selection, decodes UTF-8 across chunks, distinguishes raw lines from bounded versioned frames, and bounds queue/display sizes. Reconnect never arms. Host actuation integration and physical firmware identity acceptance remain unfinished. Raw monitor rejects reserved protocol commands.

## Content and assistant

Learner ask errors are translated by a pure presentation module using only validated diagnostic codes. Unknown codes fall back to local-hint/documentation guidance; backend message text never enters that status. Provider failure tests distinguish explicit IPC response fixtures from actual local HTTP transport and live provider credentials.

Authored lessons/guides/manual are local typed objects, with EN/KK/RU bodies and draft-review metadata. Content audit enforces IDs/fields/artifacts/counts/word thresholds and correctly fails for missing lessons. Only authored lessons have visible lesson pages.

AssistantService is disabled until provisioned. Packaged learner builds accept only managed JECTIVE configuration; renderer IPC cannot configure credentials. The administrator provisions the gateway endpoint and a learner token on first launch. Electron safeStorage encrypts that token on Windows. The provider key and model remain server-side. Legacy direct-provider paths are retained for development compatibility and isolated tests, not packaged student use. Configuration writes are serialized, validated/copied before queueing and preserve omitted credentials only for the same endpoint. A rejected update does not poison later writes. Main validates HTTPS or explicit loopback HTTP endpoints, bounds context/response, handles cancellation/timeouts and rejects redirects. Context is opt-in with exact preview. Responses are plain text; reviewed C++ diffs require explicit application and never trigger compilation/upload. Settings failures disable online requests while local educational hints remain available.

Compiler journals use a disk-backed ProcessJournal with child-pipe backpressure and an explicit 64 MiB per-operation quota. ToolchainService owns a bounded in-session operation-to-file registry; journal IPC accepts UUID/byte-offset requests, never renderer-selected source paths. JournalReader rejects escaping paths, redirected operation folders and non-files, reads at most 64 KiB, and retains trailing split UTF-8 characters for the next page. Export uses a native destination chooser and filesystem copying without a large IPC payload. The sandboxed preload imports only the pure contracts/compiler-journal schema; filesystem code stays in the main/domain layer. The expandable renderer panel displays local-path/code-sharing disclosure. Cross-session history, integrity-failure journal access and continuous output streaming remain incomplete.

Knowledge-check submissions cross a strict pure-contract preload boundary to main. The domain assessKnowledge service grades bounded answers; main persists quiz-pass progress only after success. Generic progress IPC cannot claim quiz passes. The renderer consumes the validated result and locks a pending submission; existing progress/backups are retained and are not retroactively regraded. This is local educational feedback, not a tamper-proof exam system.
