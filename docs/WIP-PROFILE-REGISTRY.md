# Versioned profile registry foundation

A filesystem-backed registry now retains imported profiles by identifier and version. It refuses replacement of the same version with different content, keeps multiple custom versions, protects built-in identifiers and resolves a selected version only when its SHA-256 matches the expected hash. Canonical hashing sorts GPIO entries, so pin-list order alone does not change identity. Writes use exclusive creation and fsync; imports never alter the bundled profile array.

Tests use real temporary directories to verify persistence across registry reopening, duplicate import, replacement rejection, version/hash mismatch, multiple versions, built-in protection and rejection of foreign or filename/content-mismatched files. All 98 unit/integration tests passed, with type checking and lint. Aggregate branch coverage is 793/878 (90.31 percent); registry coverage is 80.64 percent. The unchanged per-file gate passes.

This registry is not yet connected to IPC, UI selectors, project schema or ToolchainService. Atomic publication during write failures/power loss and concurrent import behavior still need hardening before application integration. Hashes identify definitions; they do not establish electrical correctness or reviewed provenance. The complete master specification remains incomplete, and published 0.4.0 artifacts are unchanged.

Subsequent hardening writes and fsyncs a UUID staging file, closes it, then publishes using an exclusive filesystem hard link. The final version path is never overwritten. A competing publisher compares the already-complete winning definition and returns duplicate or a version conflict. Staging files are excluded from the registry and cleaned after normal completion or error; abandoned files from interrupted runs remain unpublished. A valid staging directory is required and symlinks are refused.

Three additional real-filesystem tests passed: eight concurrent identical imports yield one import and seven duplicates with no remaining temporary files; conflicting concurrent imports yield one winner and one rejected replacement; abandoned partial staging data remains invisible. All 101 tests, type checking and lint passed; aggregate branch coverage is 804/888 (90.54 percent), registry 87.80 percent. Actual power removal, injected write/fsync/link failures and unsupported-filesystem behavior remain unverified; hard-link publication errors propagate rather than falling back to an overwriting rename. Updated reports are in evidence/wip-profile-registry-publication.

Further fault verification now covers explicitly injected open, partial-write, fsync and hard-link EIO failures with otherwise real filesystem operations. Each failure leaves no final profile, cleans the temporary file and permits a successful retry. Actual Windows staging junctions and file obstructions are rejected without writing into the outside directory or changing the obstruction. All 106 tests, type checking and lint passed; aggregate branch coverage is 806/888 (90.76 percent), registry 92.68 percent. Reports are retained in evidence/wip-profile-registry-failures. Actual power removal and unsupported-filesystem compatibility remain unverified; the injected errors are software fault fixtures, not physical power-loss evidence.
