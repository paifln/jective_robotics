# Подготовка к публикации в GitHub

README описывает запуск, возможности, структуру, сервер и фактический статус проекта. Исходники, `package-lock.json`, необходимые учебные ресурсы и тесты входят в репозиторий. Открытая лицензия не назначена: текущий статус — `UNLICENSED`.

## Что исключено

- `node_modules`, `dist`, `release`, `.toolchain`, `.verification`, `test-results`, `coverage`.
- Реальные `.env`, зашифрованные секреты, мастер-ключи, сертификаты с ключами, токены и ученические базы.
- Большие локальные скриншоты, трассы и повторяющиеся отчёты `evidence`.
- Личные настройки IDE и временные системные файлы.

Шаблоны `*.env.example` остаются в Git. Текстовые свидетельства и точные ссылки `docs/requirements.json` разрешены отдельными правилами `.gitignore`. При добавлении новой ссылки на машинный отчёт обновите это правило; иначе проверка ссылок на чистой копии обнаружит отсутствие файла.

`.gitignore` не удаляет файлы с диска и не исключает уже отслеживаемые файлы из истории Git. Проверка известных форматов секретов также не гарантирует отсутствие любой чувствительной информации: просмотрите содержимое коммита перед публикацией.

## Перед коммитом

```powershell
git status --short
npm run github:test
npm run github:check
git diff --check
```

После просмотра изменений:

```powershell
git add .
git diff --cached --stat
git diff --cached --check
git commit -m "Обновить интерфейс Windows, обучение, сервер помощника и документацию"
git push
```

Команды коммита и пуша выполняются владельцем репозитория. Не помещайте реальные ключи в команды, README, issues или сообщения коммитов. Для сервера используйте [руководство администратора](../services/assistant/DEPLOYMENT_RU.md).

Проверка кандидатов учитывает добавленные, изменённые и удалённые файлы без изменения индекса владельца. Удаление неиспользуемого исходника допустимо; оставшаяся ссылка матрицы требований на удалённый файл по-прежнему вызывает ошибку. Это поведение проверяется в отдельном временном Git-репозитории.

## Автоматические проверки

Файл [checks.yml](../.github/workflows/checks.yml) подготовлен для pull request, push в main/master и ручного запуска. Он устанавливает зависимости из lock-файла на Windows с Node.js 24, проверяет исходники, сервер на заглушках, покрытие, зависимости и несколько базовых desktop-сценариев без SDK. Ключи OpenAI для него не нужны. Workflow в GitHub ещё не запускался: локальная проверка не является результатом GitHub Actions.

Права токена ограничены чтением репозитория, checkout не сохраняет учётные данные, кеширование отключено. Оба action закреплены полными SHA официальных репозиториев, проверенными 15 октября 2026: [checkout](https://github.com/actions/checkout), [setup-node](https://github.com/actions/setup-node). При обновлении проверяйте новый коммит и его требования к runner.

Зелёный результат этого workflow не заменяет полный E2E с настоящим SDK, установку/обновление/удаление, Windows 10, языковую и учебную экспертизу, физическую плату или работу публичного сервера. Он не собирает и не публикует установщик.
